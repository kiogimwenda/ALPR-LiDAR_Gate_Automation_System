1. Introduction & Board Overview

This guide walks you through designing a custom PCB for the gate automation field controller using KiCad 10.0. The board replaces the breadboard prototype and integrates all gate-side electronics into a single, production-ready, 4-layer PCB sized to fit inside a standard IP65 enclosure.

Revision 2.0 (July 2026). This revision supersedes the April 2026 KiCad 9.0 guide. Two things changed: the tooling moved to KiCad 10.0, and — far more important — the pin map was re-synchronized with the shipped firmware (v1.0.0). Revision 1.0 predated the firmware's driver work (Phases 4.4–4.5) and disagreed with it on the entire W5500 SPI bus, the W5500 INT/RST lines, and the status LEDs; it also placed RS-485 on pins the firmware later took for LEDs, and double-booked IO21. A board routed from revision 1.0 will not run the firmware. §1.4 is now the single source of truth for every net; every schematic section and Appendix A have been corrected against it.
Revision 2.1 (July 2026). Caught during schematic review of the first built power-supply sheet. Three fixes to what is now §4.1 / Appendix B, all on the 5V buck rail: (1) the VSENSE feedback divider's R_top was wrong — 43 kΩ paired with the 10 kΩ bottom leg actually sets ~6.47V, not the claimed 5.0V; corrected to 30.9 kΩ. (2) the power-path diagram and BOM were missing two components that the component tables required but never drew: the series reverse-polarity diode ahead of the TVS, and the PH-to-GND catch/freewheeling diode the TPS5430 needs (it has no internal low-side switch) — both are now in the diagram and BOM. (3) the "C_comp / R_comp" compensation pair has been removed — the TPS5430 has no external COMP pin; compensation is fixed internally, and those two components never did anything.

Structural rewrite, prompted by building the actual power-supply and MCU schematic sheets and finding it slower than it should have been to answer "where's everything about module X." Chapters 4 (footprints) and 5 (schematics) are merged into one chapter, §4, with a dedicated section per module — footprints, schematic, and an explicit pin-to-pin connection table together, instead of split across two chapters you had to flip between. Revision 3.8 (July 2026). §4.3's crystal network was described in a single sentence of prose ("XO(31)──R16(1M)──XI(30) in parallel with the crystal...") with no actual visual layout — caught when that description alone wasn't enough to wire the network correctly. Replaced with a real diagram: R16 (1MΩ) bridges XI and XO directly, not in series with either crystal leg; the crystal's two terminals connect one each to XI/XO; each terminal gets its own 18pF load cap (C19, C20) to GND; R17, populated as a 0Ω link per WIZnet's reference, sits in series on the XI-side leg before its cap — though since it's 0Ω, which side it's physically placed on doesn't change the circuit's behavior.
Revision 3.9 (July 2026). §4.4's KiCad symbol name was wrong: Relay:SANYOU_SRD_Series_Form_C doesn't exist — the symbol is SANYOU_SRD_Form_C (no "Series"), while the matching footprint does keep "Series" in its own name, an inconsistency easy to trip over. This exact symbol also has a documented KiCad bug history (kicad-footprints#1003: schematic and footprint disagreed on which pins were connected, fixed in kicad-symbols#1527) — worth knowing about even though current libraries have the fix. Added a verified pin table (1, 2 = coil, no polarity; 5 = COM; 4 = NO; 3 = NC) and real pin numbers throughout the schematic diagram and pin-to-pin table, which previously only referred to contacts generically as "COM/NO/NC" with no pin numbers at all.
Revision 3.10 (July 2026). §4.4.1's component table has listed LED_REL and its R_LED (1kΩ, calculated off the 5V rail) since early revisions of this guide, but neither ever appeared in the schematic diagram or the pin-to-pin table — there was nowhere in the document that said where to actually connect it. Added: LED_REL sits in parallel with the relay coil, at Q_n's collector — anode through R_LED to +5V, cathode to the collector node (same node as the coil and D_flyback's cathode). This means it lights when the transistor actually conducts and the relay is energized, not just when the GPIO commands it — and explains why R_LED was always calculated off 5V rather than 3.3V.

1.1 What This Board Does

  • Runs the ESP32-S3-WROOM-1-N16R8 module as the main controller
  • Provides wired Ethernet (W5500 + RJ45) for communication with the GPU server
  • Drives up to 4 relay outputs (gate motor trigger, leaf 2, spare 1, spare 2)
  • Reads 3 digital inputs (limit switch OPEN, limit switch CLOSED, safety beam)
  • Includes RS-485 transceiver for future CENTURION motor direct-drive
  • Accepts 12V DC input, regulates to 5V and 3.3V on-board
  • USB-C port for firmware upload and debug console
  • Status LEDs for power, network link, authorization, and fault

1.3 Design Philosophy

  • Reliability first: Generous trace widths, proper decoupling, TVS protection on all external I/O
  • Hand-solderable: No components smaller than 0603 (1608 metric). QFP/QFN packages have 0.5mm+ pitch
  • Testable: Test points on all power rails and critical signals
  • Expandable: Two spare relay channels + unpopulated headers for future use

File format is one-way. KiCad 10 opens KiCad 9 projects and upgrades them on save, but files saved by v10 cannot be opened in v9 or earlier. Everyone touching hardware/pcb/ must be on 10.x before the first save, and the KiCad version belongs in the commit message when the design files land in git.
New in 10.0, used later in this guide: the graphical DRC rule editor (§7), reusable design blocks for the repeated relay-driver channel (§6), and 3D PDF export for checking enclosure fit (§8). Cosmetic but welcome: system dark mode is honored (theme under Preferences → Colors) and toolbars are freely rearrangeable.

Three polarities that are easy to get backwards — verify each in schematic ERC and again visually before layout:
  • C_boot connects BOOT to PH, not to GND. Tying it to GND removes the high-side FET's gate-drive supply — the regulator will not switch correctly.
  • D7 (reverse-polarity) must pass forward current in the normal direction: anode toward the polyfuse/connector, cathode toward the TVS/VIN node. Backwards, it blocks all current.
  • D5 (catch diode) cathode goes to PH, anode to GND — it needs to conduct from GND into PH while the high-side switch is off. Backwards, it does nothing (or clamps the wrong direction).

Critical Layout Rules

  • Antenna keepout: No copper (traces, ground fill, vias) within 15 mm of the antenna end of the module (opposite the castellated pads).
  • Ground plane: Connect the center EPAD to the GND plane with at least 9 thermal-relief vias (0.3 mm drill, 0.6 mm pad).
  • Board edge: The antenna end should extend to or overhang the board edge. Place the module at a board corner if WiFi/BLE is ever needed.
The exposed pad's GND connection is automatic — but only if your ground net is literally named "GND" somewhere. The official KiCad symbol has 39 visible pins plus two hidden pins, 40 and 41, both named GND — pin 40 is a real spare ground pin on the physical package, pin 41 maps to the large exposed thermal pad. Neither appears on the schematic canvas or in a casual pin-properties check; they use KiCad's auto-connect mechanism for hidden power pins, which joins by matching pin name to any globally-named net or power symbol — not by wire, not by proximity. If your project's ground label is something other than plain GND (e.g. GNDPWR), these hidden pins will not find it and end up on an isolated, undriven net of their own. Fix: place one plain GND power symbol anywhere already wired onto your ground net (e.g. right next to the module's visible GND pin) to bridge the two names. Verify: run ERC — an unconnected/undriven power pin on the ESP32 symbol before the bridge, clean after, confirms it either way.

D+ and D- are each two separate, both-visible pins — tie them together; VBUS and GND are not. Unlike VBUS (A4, with A9/B4/B9 hidden) and GND (A1, with A12/B1/B12 hidden) — which auto-connect to their duplicates via KiCad's hidden-power-pin name matching, the same mechanism as the ESP32 module's hidden GND 40/41 in §4.2.1 — D+ and D- have no hidden pins. A6/B6 (D+) and A7/B7 (D-) are both ordinary visible pins you must wire together yourself: this is what makes the connector reversible for USB 2.0 signaling, since either physical pin carries the signal depending on which way the plug is inserted. Wire A6 and B6 to the same net, A7 and B7 to the same net, and put a single 22Ω resistor on each combined net — not one resistor per physical pin.
Important: The Schottky diode on VBUS prevents the 12V→5V buck converter from back-feeding power out the USB port. Without this, connecting USB while 12V is applied would try to power the host computer.
U6 pin 5 is VBUS, not a ground/shield pin. A common mistake (this exact one has been caught during schematic review on this project) is wiring pin 5 into the shield RC-filter chain toward GND instead of to VBUS, and leaving pins 1/3/4/6 — the pins that actually clamp D+/D- — unconnected. Wired that way, the IC sits on the board doing nothing. Double-check pin 5 lands on the VBUS net and pins 1/6 and 3/4 land on D-/D+ respectively.
U6 goes between the connector and the 22Ω resistors, not between the resistors and the ESP32. Also caught during schematic review: it's easy to wire R_D+/R_D- directly off J1's D+/D- pins and then hang U6 off the resistors' far side (the same net the ESP32 sits on) — the diagram above and the resistor tables list the connector's pins in that order, and U6 reads like an afterthought tacked onto whichever net is closest. Wired that way, U6 still clamps something, but the series resistor now sits in the fast-transient path before the clamp engages, which is exactly the impedance an ESD clamp is supposed to see zero of. J1's D+/D- pins should land on U6's I/O pins directly; R_D+/R_D- go between U6 and the ESP32-side net, not between J1 and U6.

4.2.5 Programming & Debug Header Wiring

Neither header is required for normal use. The primary flash/monitor path is the USB-C port itself — the ESP32-S3's built-in USB-Serial/JTAG peripheral (the same IO19/IO20 already wired in §4.2.4) handles firmware flashing, the serial console, and JTAG debugging over that one connector, no extra hardware needed. Note: The relay coil is powered from the +5V rail, NOT 3.3V. The NPN transistor level-shifts the 3.3V GPIO signal to switch the 5V relay. The flyback diode MUST be present — without it, the back-EMF from the relay coil will destroy the transistor.
LED_REL sits in parallel with the coil, at the same collector node — not off the GPIO. Anode → R_LED (1kΩ) → +5V; cathode → Q_n's collector (the same node the coil and D_flyback's cathode land on). When Q_n is off, the collector sits near +5V (pulled up through the coil, which drops negligible voltage at zero current), so there's ~0V across the LED and it stays dark. When Q_n conducts, the collector drops to ~0.2V (Vce_sat), putting the full ~4.8V across R_LED+LED_REL and lighting it — exactly when the relay is actually energized, not just commanded. This is also why R_LED is calculated off the 5V rail rather than 3.3V: it's part of the same 5V-side cluster as the coil and flyback diode, not tied directly to the 3.3V GPIO signal.

  3. Net: GND
  4. Draw zone covering the entire board outline
  5. Critical: Do NOT cut this plane. An unbroken ground plane is the single most important factor for EMI performance and signal integrity.
  6. The only acceptable break: a narrow slot under the antenna keepout zone of the ESP32-S3 (but even this should be a keep-out, not a plane cut)

Layer 3 (In2.Cu) — Power Planes

  1. Create 3 zones on In2.Cu:
    • +5V zone: Covers the relay section and feeds the LDO. Approximately 60% of board area.
    • +3.3V zone: Covers the ESP32-S3 and W5500 area. Approximately 35% of board area.
    • +12V zone: Small island near the power input and safety beam connector. Approximately 5%.
  2. Zone priority: +12V = 1, +5V = 2, +3V3 = 3 (higher priority fills first where zones overlap)
  3. Leave 0.5mm gap between power zones

6.4 Signal Routing

Routing Order (route in this sequence for best results)

  1. USB differential pair — most impedance-sensitive. Route first while the board is uncongested.
    • Use Route → Differential Pair in KiCad 10.0
    • Set pair gap to 0.15 mm in Net Classes
    • Route on Top layer only (F.Cu), directly over the unbroken GND plane
    • No vias on the differential pair
  2. 25 MHz crystal traces — short, symmetric, with ground guard.
    • Route on Top layer, keep traces under 5mm
    • Place ground vias around both crystal pads
  3. SPI bus (ESP32 → W5500) — parallel routing, same layer
    • Route CLK, MOSI, MISO, CS as a group on F.Cu
    • Keep traces parallel with 0.3mm minimum spacing between them
    • Maximum length: 50mm. Target: 30mm or less.
  4. Power traces — thick traces on F.Cu connecting to power plane vias
    • Buck converter SW node to inductor: 1.5mm wide, as short as possible (<5mm)
    • Use multiple vias (3–4) to connect power traces to their respective inner-layer planes
  5. GPIO signals — relay drivers, LED outputs, sensor inputs
    • Standard 0.25mm traces
    • Route relay control signals on B.Cu (bottom layer) to keep them away from the sensitive top-layer signals
  6. RS-485 bus
    • Route A and B as a differential pair (100Ω, though less critical than USB)
    • Keep traces parallel, short run to the screw terminal

Routing Tips in KiCad 10.0

  • Interactive router: Press X to start routing, V to place a via and switch layers
  • Push-and-shove: Enable in Interactive Router Settings (gear icon) — it moves existing traces out of the way as you route
  • Length tuning: After routing the USB pair, use the tuning tool to add serpentine to the shorter trace. KiCad 10 overhauled tuning (Tuning Profiles, time-domain constraints) — overkill for USB full-speed, but the profile UI is the same one you'll use.
  • Teardrops: After routing, run Edit → Apply Teardrops — adds reliability to pad-trace connections
  • Design blocks (new in 10): The relay driver channel repeats four times — place and route one channel cleanly, save it as a design block, and stamp the other three. Same for the three sensor-input protection channels.
  • Lasso selection (new in 10): Freeform area select makes grabbing one routed channel for duplication much less fiddly than rectangle-select ever was.

6.5 Antenna Keepout Zone

  1. Identify the antenna end of the ESP32-S3-WROOM-1 module (the narrow end, opposite the castellated pads)
  2. On ALL copper layers (F.Cu, In1.Cu, In2.Cu, B.Cu), create a Rule Area:
    • Click Place → Rule Area
    • Check: "Keep out copper fill", "Keep out tracks", "Keep out vias"
    • Draw a rectangle extending 15mm from the antenna end
  3. No components should be placed in this zone on any layer
  4. The board edge should be at or within this zone (antenna overhangs board edge = best performance)
If you skip this step: The WiFi/BLE range will be reduced by 50–80%. To be clear about today's posture: the shipped system needs no radio — control, telemetry, and OTA all run over the W5500 wired Ethernet (ADR-011 / ADR-009). The keepout is cheap insurance for the futures that do want the radio (WiFi as a network fallback, BLE commissioning) and good RF hygiene regardless — don't spend it on copper.

6.6 Thermal Relief & Copper Fills

  1. Top and Bottom copper fills: After all routing is complete, add GND fills on F.Cu and B.Cu:
    • Place → Zone, Net = GND, covering entire board
    • Set zone clearance to 0.3mm (slightly larger than default to avoid acid traps)
    • Set minimum island area to 5 mm² (removes useless copper fragments)
  2. Thermal relief on pads: KiCad defaults to thermal relief (spoked connections) for pads connected to copper fills. Keep this default — it makes hand soldering possible. For the ESP32 GND pad and the TPS5430 exposed pad, consider direct connection (solid) for better thermal performance.
  3. Via stitching: After fills, add via stitching to connect F.Cu GND fill to the L2 GND plane:
    • Place vias on a 5mm grid across the board (where space allows)
    • In KiCad 10.0: Edit → Fill All Zones, then use the via stitching plugin or manually place vias connected to GND

10. Assembly & Testing Checklist

10.1 Solder Order (if hand-assembling)

  1. Shortest components first: SMD resistors and capacitors (0603) using solder paste + hot air or iron with fine tip
  2. ICs: W5500 (LQFP-48) — use flux + drag-solder technique. Then MAX485 (SOIC-8), SS8050 transistors (SOT-23)
  3. Medium-height: AMS1117 (SOT-223), TPS5430 (HSOP-8), crystal, USB-C connector, LEDs
  4. Tall components last: ESP32-S3 module (castellated pads — use lots of flux, solder one corner first, align, then all pads). Electrolytic capacitor. Inductor.
  5. Through-hole last: Relays (4×), screw terminals, RJ45 jack, pin headers, mounting standoffs

10.2 First Power-On Test Sequence

  1. Visual inspection: Check for solder bridges (especially on W5500 QFP and ESP32 module). Use magnification (loupe or microscope).
  2. Continuity check: With multimeter in continuity mode:
    • Verify no short between +12V and GND
    • Verify no short between +5V and GND
    • Verify no short between +3.3V and GND
  3. Power-on (12V): Apply 12V to J_PWR. Measure:
    • TP_5V: should read 4.9–5.1V
    • TP_3V3: should read 3.25–3.35V
    • LED_PWR: should illuminate green
  4. USB test: Connect USB-C cable. Computer should enumerate a USB device (ESP32-S3).
  5. Flash test firmware: Flash the real gate firmware (cd firmware && idf.py flash monitor). Expect the boot banner and the bare-bench Faulted state described in the bench validation plan Stage 1 — on this board the status LEDs (red/green/yellow) show the fault pattern. (Unlike the DevKit, the bare WROOM module has no onboard RGB LED — rev 1.0's "RGB should blink" check was a DevKit-ism.)
  6. Ethernet test: Connect Ethernet cable. LED_NET should illuminate. Ping test to server IP.
  7. Relay test: Run GPIO toggle test. Listen for relay click. Verify continuity across NO contacts with multimeter.
  8. Input test: Short each sensor input to GND. Firmware should register the state change.
